## 1. 真实错误案例最终确认（typing-extensions）

- 证据标准：对应版本制品的许可证原文（LICENSE 文件内容）、各来源的字段定义文档、判定依据链。
- 若无法证明：删除 DOWNSTREAM_PARSING_ERROR 责任断言，换一个能证明的真实案例（给出新案例的包名/版本/证据）。
- 输出：`evidence/real-error-case.md`（案例＋证据链＋结论：成立/不成立/换案例）。

## 2. 延迟时间链核验（archgraph-layout）
- 现状：该案例已降级为"疑似延迟，时间链待核验"（07:03:12Z 报告引用 07:15:00Z 观察，时间倒序）。
- 要求：检查原始 HTTP 响应、采集日志（run.log、evidence/snapshots），看能否解释矛盾。
- 若能解释：写清解释链条，恢复为"已证明的延迟范围"（只写可证明的范围）。
- 若不能解释：保持 suspect/retracted，重新采集一个干净的延迟案例（真实 404→后续出现，时间链完整）。
- 输出：更新 `evidence/delay-chain.md`（解释或重采记录）。

## 3. 自然不可判定案例
- 要求：找一个**真实**的自然不可判定案例（真实缺证或真实不可比条件，非构造）。
- 证据标准：包名、版本、坐标、缺失了什么证据、为什么不可比。
- 输出：加入 evidence/ 并更新案例清单。
